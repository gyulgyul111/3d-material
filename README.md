# 랙 재고 카운팅 (객체인식 + 깊이추정)

특정 랙을 찍은 사진 한 장에서 박스라벨을 검출하고, 단안 깊이추정으로 안쪽에 가려진 박스까지 추정합니다.
라벨링 클래스가 곧 부자재이며, 그렇게 구한 클래스(부자재)별 재고가 적정재고 이하이면 구매필요수량을 계산합니다.

```
사진 ─ ROI(랙 네 모서리) 원근 보정 ─┬─ YOLO (박스라벨 검출)
     └─ Depth Anything V2 Metric ─ 같은 보정 ─┴─ 랙 앞면 기준 깊이로 레인별 수량 추정 ─ 부자재별 재고 ─ 구매필요수량
```

## ROI (랙 네 모서리)

랙마다 기준 사진에서 **랙 앞면 프레임의 네 모서리**를 찍습니다. 그러면 그 사각형이 원근 보정되어 정면 직사각형 이미지가 되고,
사각형 밖(옆 랙, 바닥, 천장 등)은 **라벨링, 학습, 추론에서 모두 제외**됩니다.
라벨링용 사진도 **업로드할 때 반드시 랙 ROI로 보정**되므로, 학습과 추론이 같은 모양의 이미지를 보게 됩니다.

- 원본은 `datasets/box_label/originals/`에 보관합니다. 나중에 랙 ROI를 바꾸면 라벨링 목록에 **ROI 변경됨**으로 표시되고,
  [ROI 적용]을 누르면 원본에서 새 ROI로 다시 보정합니다. 이때 **라벨 박스 좌표도 같은 변환으로 옮겨지므로 다시 라벨링할 필요가 없습니다**.
- ROI 없이 들어온 예전 이미지나 외부에서 가져온 이미지는 **ROI 미적용**으로 표시되고 학습에서 제외됩니다. [ROI 적용]을 누르면 라벨과 함께 보정됩니다.
- ROI 밖으로 절반 이상 나가는 박스는 보정할 때 지워집니다.

## 수량 추정 원리

선반은 앞에서부터 꺼내 쓰고 남은 박스는 뒤쪽에 붙어 있다고 가정합니다. 그러면 보이는 라벨, 즉 레인 맨 앞 박스의 앞면이
**랙 앞면보다 얼마나 안쪽으로 들어가 있는지(recess)** 를 보고 그 레인에 남은 박스 수를 알 수 있습니다.

```
레인 수량 = floor((랙 깊이 − recess + 허용오차) / 박스 깊이)      (1 ~ 최대 적재열 사이로 제한)
부자재 수량 = Σ 그 클래스 라벨별 레인 수량        (위로 쌓인 박스는 라벨이 각각 보이므로 각각 카운트)
```

- **랙 앞면**은 ROI 네 모서리(랙 프레임)의 깊이를 이어서 만든 면입니다. 랙이 비스듬해도 위치마다 앞면 깊이가 보간됩니다.
- **부자재**는 검출된 클래스입니다. 클래스별 **박스 깊이**, 재고 기준, 색상은 [클래스(부자재)] 탭에서 관리합니다.
- `camera_to_front_m`(카메라에서 랙 앞면까지 실측 거리)를 넣으면 깊이모델의 스케일 오차를 보정합니다. **입력을 권장합니다.**
- 랙 안쪽 끝보다 더 깊은 라벨은 뒤쪽 랙이나 배경으로 보고 제외합니다.
- **[깊이 추정·3D]** 탭에서 거리 맵, 랙 앞면 기준 깊이 맵(마우스를 올리면 mm 값 표시), 3D 재구성(메시 또는 포인트)을 확인할 수 있습니다.

## 구매필요수량

| 조건 | 계산 |
|---|---|
| 현재고 > 적정재고 | 구매 불필요 |
| 현재고 ≤ 적정재고 | `ceil((목표재고 − 현재고) / 발주단위) × 발주단위` (최소 1 발주단위) |

EA 수량은 `구매박스 × 박스당 입수량`입니다. 적정재고와 목표재고가 모두 0인 클래스는 수량만 세고 구매 판단은 하지 않습니다.
기준정보는 [config/racks.yaml](config/racks.yaml)의 `classes`에 있으며, 목록 순서가 라벨 파일의 클래스 번호입니다.

## 설치 (다른 PC에서 시작하기)

```powershell
git clone https://github.com/gyulgyul111/3d-material.git
cd 3d-material
setup.bat          # 가상환경 생성 + 패키지 설치 (처음 한 번)
run_server.bat     # 서버 실행 + 브라우저 열기
```

- Python 3.12 이상이 필요합니다. NVIDIA GPU가 없어도 CPU로 동작하지만 학습은 매우 느립니다.
- 첫 실행 때 깊이 모델(Depth Anything V2)을, 첫 학습 때 YOLO 기본 가중치를 인터넷에서 내려받습니다.
- **저장소에는 코드와 설정(`config/racks.yaml`: 랙 ROI, 클래스)만 들어 있습니다.** 라벨링 사진(`datasets/`), 랙 기준 사진(`data/`),
  학습 모델(`models/`)은 올리지 않으므로 새 PC에서는 기준 사진과 라벨링 사진을 다시 올리고 학습해야 합니다.
  기존 PC의 작업을 그대로 옮기려면 위 세 폴더를 직접 복사하세요.

수동 설치:
```powershell
python -m venv .venv
.venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
```

## 실행

`run_server.bat`을 더블클릭하면 서버가 켜지고 브라우저가 열립니다(http://localhost:8000).
같은 네트워크의 스마트폰에서는 `http://<PC IP>:8000`으로 접속해 바로 촬영하고 올릴 수 있습니다.

## 웹에서 하는 작업 순서

| 탭 | 하는 일 |
|---|---|
| **1. 랙·ROI 설정** | 랙 추가, 기준 사진 업로드, 랙 네 모서리 찍기(돋보기로 미세조정), 보정 결과 미리보기, 랙 깊이·이 랙의 부자재 지정, 분석 파라미터 조정 |
| **2. 클래스(부자재)** | 클래스 추가·이름변경·삭제·순서변경, 색상 지정, 클래스별 적정재고·목표재고·발주단위·박스당 입수·박스 깊이. 삭제하면 그 클래스의 라벨 박스도 지워지고 번호가 당겨짐 |
| **3. 라벨링** | 사진 여러 장 업로드(랙 ROI로 자동 보정, 원본 보관), ROI 미적용·변경 이미지 일괄 적용(라벨 좌표 자동 변환), 박스라벨 영역에 bbox 그리기(단축키 지원), 클래스 관리, 학습된 모델로 초벌 라벨 |
| **4. 학습** | 기본 모델과 epoch 등을 정해 학습 시작·중지, 진행률·mAP 차트·로그 확인. 끝나면 새 모델이 분석에 바로 적용 |
| **재고 분석** | 랙을 선택하고 사진을 올려 재고와 구매필요수량 확인, CSV 다운로드. 분석한 사진을 라벨링 데이터에 추가 가능 |
| **깊이 추정·3D** | 깊이 모델 결과 확인: 거리 맵, 랙 앞면 기준 깊이 맵, 3D 재구성(회전, 확대, 시야각 조정) |

라벨링 팁
- 박스라벨 스티커 영역에만 꼭 맞게 그리세요. 실제 운영과 같은 카메라 위치에서 조명과 적재량을 다양하게 찍어 **200장 이상** 모으는 것을 권장합니다.
- 박스 없이 저장한 사진은 '라벨 없음' 사례로 학습되어 오검출을 줄여줍니다.
- 클래스를 추가·삭제·이름변경하면 검출 모델을 다시 학습해야 분석에 반영됩니다. 필요하면 화면에 안내가 표시됩니다.
- 처음 수십 장을 라벨링해 학습한 뒤 **[모델로 초벌 라벨]** 기능으로 나머지를 빠르게 검수하는 방식이 효율적입니다.

데이터 위치
- 랙·클래스 설정: `config/racks.yaml` (웹에서 저장하면 파일 안의 주석은 사라집니다)
- 라벨링 데이터: `datasets/box_label/` (YOLO 포맷, `originals/` 원본, `roi.json` 이미지별 적용 ROI)
- 모델: `models/box_label.pt`
- 학습 기록: `runs/`
- 분석 이력: `data/history.jsonl`

다른 툴(CVAT, Roboflow 등)에서 YOLO 포맷으로 라벨링해둔 데이터는 아래 명령으로 가져옵니다.
```powershell
python scripts/import_yolo.py <폴더>     # <폴더>/images, <폴더>/labels, (선택) <폴더>/classes.txt
```

## 정확도를 위한 운영 가이드

- **카메라 위치 고정**: ROI가 고정 좌표이므로 매번 같은 위치와 화각에서 찍어야 합니다. 삼각대나 고정 카메라를 권장합니다.
- **ROI 모서리**: 박스에 가려지지 않는 랙 프레임(기둥과 빔의 교차점)에 찍으세요. 네 모서리의 깊이가 랙 앞면 기준이 됩니다.
- **정면에 가깝게 촬영**: 너무 비스듬하면 보정 후 먼 쪽의 라벨이 작고 흐려져 검출이 어려워집니다.
- **ROI를 바꾸면**: 보정 이미지 모양이 달라지므로, 크게 바꿨다면 라벨링 데이터를 새로 모아 다시 학습하는 것이 좋습니다.
- **검증**: 초기에는 실사 재고와 비교해 `depth_tolerance_ratio`(기본 0.3)를 조정하세요.
- **한계**: 한 레인 안에서 중간이 빈 경우처럼 앞에서 꺼내 쓰지 않는 적재 방식은 추정할 수 없습니다.
